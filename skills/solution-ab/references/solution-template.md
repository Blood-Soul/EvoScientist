# 方案骨架（A / B 两组共用）

两组方案必须使用**完全相同**的这套骨架。骨架一致是对比成立的前提 —— 只有结构固定，差异才能归因到上下文本身，而不是格式或详略程度的偶然波动。

按顺序输出以下 6 节，节标题逐字沿用，不增删不重排。

---

## 1. 方案概述

一段（4–6 句）。说明：解决什么问题、核心思路是什么、预期达到什么效果。
直接陈述方案本身，不要复述问题背景，不要写"本方案将……"这类开场套话。

## 2. 关键设计决策

3–5 条。每条格式：

```
- **<决策一句话>** —— <为什么这样选，具体依据是什么>
  依据：<出处>
```

「依据」必须指向上下文中的具体位置：
- A 组 → 经验条目 id（如 `L1-003`、`L2-002`）
- B 组 → 论文章节或表格（如 `§4.2`、`Table 3`、`abstract`）

上下文没有依据支撑的决策 → 标注 `依据：上下文未覆盖`，不要编造出处。

## 3. 实施步骤

可操作的有序序列。每步是一个能落地的动作，不是抽象目标。
带上具体参数、阈值、配置时必须来自上下文（并在括号内注明出处）；上下文没给的参数写"需自行确定"，不要臆造数值。

✅ `3. 用 top-3 检索历史成功案例作为示例注入（L1-004 给出的检索深度）`
❌ `3. 优化检索策略`

## 4. 验证方式

怎么判断这个方案有效。包含：
- **指标**：用什么衡量（尽量用上下文里出现过的指标名）
- **对照**：跟什么比
- **判定线**：达到什么程度算成功；上下文有具体数值就引用，没有就写"上下文未给出基准值"

## 5. 风险与边界

- **失效条件**：什么情况下这个方案不适用
- **已知代价**：计算成本、延迟、工程复杂度等（上下文提到就引用具体数字）
- **未验证假设**：方案依赖但上下文没有证据支持的部分 —— 这一项要诚实列出

## 6. 依据来源清单

列出本方案实际引用过的所有出处，去重后按出现顺序排列。

- A 组示例：`L1-001, L1-004, L2-002`
- B 组示例：`abstract, §3.2, §4.1, Table 3`

末尾单独一行记录上下文规模：`上下文规模：<字符数> 字符`

---

## 硬约束（两组同等适用）

1. **只用给定上下文**。不得引入上下文之外的知识、论文、经验或常识补充。这一条是对比有效性的核心 —— 一旦掺入模型自身先验，差异就不再归因于上下文。
2. **上下文没有 → 明说没有**。写 `上下文未覆盖`，不要用通用最佳实践填补空缺。
3. **数值必须可溯源**。任何具体数字都要能在上下文中找到，并注明出处。
4. **不评价另一组**。写 A 时当作 B 不存在，反之亦然。不要出现"相比另一方案……"这类表述。

# L1 → L2 归纳：按聚类中心归纳 L1 的共性

状态：第二版实现（2026-11-24），代码在 `EvoScientist/memory/experiences/cross_paper.py`，prompt 在
`prompt/l2_from_l1_cluster.md`。阈值是在 judgelab 的 L1 库上定的暂定值，见 §7。第一版设计（LLM 分组 + 逐条增量操作）
见 git 历史 `c4fba3d`，和本版的差别见 §9。

## 1. L1 和 L2

| | L1 | L2 |
|---|---|---|
| 是什么 | 一篇论文测过的一个做法：改了什么、在什么设置下、结果如何 | 多条 L1 的**共性**：什么条件下做什么、为什么、代价和边界 |
| 来源 | 论文原文 | 一个聚类里的 L1，至少 3 条，来自哪篇论文不限 |
| 依据 | 原文：数字在文中、引文、locator | 所引 L1 的 id；数字必须出现在所引 L1 里 |
| 具体程度 | 绑定具体数据集、模型、参数值（`source_setting`） | 去掉具体值，写成条件（`requires`）和选项对比（`compared_options`） |
| 机制 | 这一个实验的解释，`stated`（论文给的）或 `inferred`（推出来的） | 几条记录共同支持的解释 |
| 会不会变 | 抽出来就不变，是一条事实 | 随证据变：加强、收窄、出现冲突、被推翻 |
| 下游怎么用 | 当证据："别人这样做过，结果如何" | 当决策规则：plan review 把它变成"先检查这个前提" |

**论文只抽 L1，L2 只从 L1 归纳。** 不再从论文原文直接抽 L2（`l2_extract_v2.md` 已删除）。这样每条 L2 都能指出它依据的
是哪几条 L1，而 L1 再指回原文。L2 的文字不要求在 L1 里逐字出现，这是从具体到抽象的一步；但依据列表由代码维护，
模型不能丢掉或编造来源。

## 2. 参考过的做法（摘要）

| 做法 | 借鉴什么 | 不照搬什么 |
|---|---|---|
| RAPTOR (2401.18059) | 先聚类再对簇做总结 | 一次性离线重建、无出处 |
| GraphRAG (2404.16130) | 社区报告引用元素 id | 需要实体图、无增量 |
| Zep/Graphiti (2501.13956) | 新记录按邻居归入已有簇，簇摘要增量更新；冲突的旧结论标为失效而不是删除 | 时序图 |
| ACE (2510.04618) | 不要整段重写：整段重写出现过"上下文坍缩"（18k token 缩到 122，准确率 66.7→57.1） | — |
| ExpeL (2308.10144) / Mem0 (2504.19413) | 结论要能被新证据加强、修改、削弱 | 无出处的投票 |
| Generative Agents (2304.03442) | `insight (because of 1, 5, 3)` 这种最简单的出处格式 | — |
| BERTopic / HDBSCAN | 允许离群点：不强行把每条记录塞进一个有结论的簇 | — |

文献里没有直接比较"增量修改 vs 整簇重写"对总结质量影响的实验，也没有关于最小簇大小的实证；下面的设定是基于这些
间接证据和 §7 的离线测量做的设计选择。

## 3. 流程

```
论文抽取 + gate 之后，L1 入库
   │
   ▼
新 L1 累计 ≥ 15 条，或有上次失败待重试的类？ ──否──> 等待
   │是
   ▼
归入：每条新 L1 找最近的聚类中心，余弦 ≥ 0.30 就加入，否则自己开一个新类
   │
   ▼
拆分：有变化的类如果超过 12 条，或太散（成员到中心的平均余弦 < 0.40），一分为二，直到每一部分都合格
   │
   ▼
判断哪些类到期（§3.3），到期的类调用一次归纳 prompt
   │
   ▼
写回 L2，延续版本号；没人接替的旧 L2 标为退役
```

### 3.1 相似度

配置了 embedding 服务（`EVOSCIENTIST_EMBEDDING_URL`，默认模型 Qwen3-Embedding-0.6B，见 §10）时，用 **embedding 余弦**：
视图文本是带标签的字段，每个字段一次（`Problem: … / Method: … / Task: … / Requires: … / Action: … / Mechanism: …`），
按文档侧编码（不加 instruction）。向量按文本缓存，一条 L1 只编码一次。

没有服务或服务失败时，退回**按字段加权的 TF-IDF 余弦**：

- 视图文本 = `problem` ×2 + `method`（名称 + 别名）×2 + `task` + `requires` + `action` + `mechanism.text`。
- 去掉停用词和领域里到处都有的泛词（model / training / performance ……），IDF 在当前库上算。
- 不区分来源论文：同一篇论文里几个相关的消融，和不同论文里的同类记录一样可以聚到一起。

聚类中心是成员向量之和再归一化，每次触发都按当前向量重新计算（TF-IDF 下会跟着库的词汇变化）。

两种向量的余弦不在一个尺度上（embedding 下无关记录之间也有 0.3–0.4），所以各有一套加入阈值和一致性下限（§7）。
state 记下聚类用的是哪种向量（`backend`）；换了一种，整库重新聚类，旧 L2 交给持有其多数依据的新类，并在这次触发
里按新成员更新，和拆分时一样；没有新类持有其多数依据的旧 L2 退役。

### 3.2 归入和拆分

- **归入**：新 L1 和所有现有中心算余弦，取最大的。达到加入阈值（TF-IDF 0.30，embedding 0.75）就加入这个类，并更新
  中心；否则自己开一个新类。
  **只有一两条的类也保留中心**，后来的相关记录才有地方汇合，类才能长大。
- **拆分**：一个类超过上限（12 条），或成员到中心的平均余弦低于下限（TF-IDF 0.40，embedding 0.78），就做一次
  2-means：以离中心最远的成员和
  离它最远的成员为种子，迭代至多 10 轮。拆出来的每一部分再检查，直到全部合格。
- 拆分后，最大的那一部分继承原来的 L2，并立刻更新（它的 L2 里有些依据已经不在这个类里了）；其余部分从零开始。
- 被重新抽取或被 gate 丢掉的 L1 会从所在的类里移除。

### 3.3 什么时候归纳、什么时候更新

一个类到期的条件：

| 类的状态 | 到期条件 |
|---|---|
| 成员 < 3 | 不到期：有中心，没有 L2 |
| 成员 ≥ 3，还没有 L2 | 到期：首次归纳 |
| 已有 L2 | 上次归纳以后新加入的成员数 ≥ max(2, ⌈0.5 × 上次归纳时的成员数⌉) |
| 刚被拆分 | 到期 |

例如上次归纳时有 3 条，要再来 2 条才更新；有 8 条，要再来 4 条。没到期的类只把新成员挂进去，L2 不动。
某个类的归纳调用失败，下次触发时补跑，即使新 L1 不够 15 条。

**为什么要攒够了再更新。** 一条新 L1 加入后，对已有 L2 的影响大致有四种：再次证实（最常见）、扩展一个条件或选项、
出现冲突、出现新规律。只有最后一种需要新的结论；每来一条就重写，会让结论和 id 频繁变化，也可能悄悄丢掉已有的
条件和局限（ACE 的坍缩）。在 judgelab 库上按每批 15 条回放，"类一变就整类重写"共调用 236 次，攒够再更新是 187 次。

### 3.4 首次归纳和更新

两者用同一个 prompt（`l2_from_l1_cluster.md`），区别在输入：

- **首次归纳**：输入只有 `records`（类的全部成员）。模型找出这些记录的共性，写出至多 3 条 L2。
- **更新**：输入多一个 `current_findings`（现有 L2，依据 id 已换成这次调用的本地 id）。模型在原结论上修改，不重写：
  - 新证据没改变的结论**一字不改**，只把新记录补进 `support`；
  - 只改新证据影响到的部分（条件、选项、局限、原因），其余保留；
  - 和结论冲突的新记录写进 `conflicts`，不覆盖原结论；
  - 现有 L2 没覆盖的新规律才新增；只有证据表明结论本身错了（不只是有局限）才删除。

结论措辞不变，L2 的 id（由 domain / task / problem / action 加类 id 算出）就不变，下游的引用和缓存不会失效。

## 4. L2 的格式

```json
{
  "domain": "...", "task": "...",
  "problem": "这一类问题，用实践者在知道答案之前的话说",
  "method": ["这一类做法的名称", "别名"],
  "action": "归纳出的结论，写成指令：什么时候做什么、换来什么",
  "compared_options": [{"option": "...", "result": "...", "from": ["E-..."]}],
  "mechanism": "几条记录共同支持的原因；没有就留空",
  "requires": [{"text": "...", "basis": "inferred", "from": ["E-..."]}],
  "limits_stated": [{"text": "...", "from": ["E-...", "E-..."]}],
  "conflicts": [{"text": "一些记录发现……而另一些发现……", "from": ["E-...", "E-..."]}],
  "origin": "cross_paper",
  "locator": "",
  "source_l1_ids": ["E-...", "E-...", "E-..."],
  "source_papers": ["2101.00438", "2108.05857"],
  "cluster_id": "c17",
  "layer": "l2"
}
```

规则在代码里检查，不只写在 prompt 里（`validate_finding`）：

- `support` 至少 3 条，且必须是类成员；每个 `from` 也必须是类成员，否则这一项被删掉。
- `limits_stated` 只能总结成员 L1 里作者自己说的局限，至少引用 2 条有局限的 L1；不从代价里取，不从机制里推。
- `compared_options` 和 `action` 里的数字，超过一半找不到出处（所引 L1 里没有）时整条 L2 丢弃。
- 结论之间有冲突时写进 `conflicts`，至少引用 2 条记录，不抹平。
- `source_papers` 由代码根据依据填写；渲染时写明"N 条实验记录，来自一篇 / M 篇论文"，读者能看出证据的分量。

## 5. 存储

L2 不属于任何一篇论文，存在项目目录下的独立文件：

```
experiences/projects/<P>/_cross_paper/
  metadata.json   # 让现有的 list_experience_documents 把它当作一个"虚拟论文目录"读取
  l2.json         # 当前有效的 L2
  state.json      # version 2：类（成员、L2 id、上次归纳时的成员数、是否刚拆分）、待重试的类、退役的 L2、触发历史
```

检索、渲染、plan review 都不用改读取路径。每条有效 L2 在 `state.json` 里记有版本号和上一版的 id（`lineage`）：
新 L2 和类里旧 L2 的依据重合度（Jaccard）≥ 0.5 时接上版本号；没有新 L2 接替的旧 L2 移到 `retired`，保留原文，
不再被检索。第一版的 `state.json`（version 1）读到时不复用，其中的 L2 全部移到 `retired`，L1 重新聚类。

## 6. 运行方式与开关

- 开关 `memory_cross_paper_enabled`（环境变量 `EVOSCIENTIST_MEMORY_CROSS_PAPER_ENABLED`），**默认打开**：这是 L2 的唯一
  来源，关掉后库里不会有新的 L2。
- 触发点：论文经验 worker 每完成一次 drain、或前台 `extract_paper_experiences` 存完论文后调用 `schedule_cross_paper`；
  在后台运行，抽取不等它。一把文件锁保证同一项目同一时刻只有一个归纳任务。
- LLM 调用并发 6，单次调用超时 900 秒。
- 每次触发写一条 trace（`cross_paper_induce`：L1 数、新增数、类数、到期与等待的类数、生成 / 延续 / 退役的 L2 数、耗时）。
- 失败只记录，不影响抽取和 agent 主流程。

## 7. 参数

| 参数 | 值 | 环境变量 | 依据 |
|---|---|---|---|
| 触发间隔 | 15 条新 L1 | `EVOSCIENTIST_CROSS_PAPER_EVERY` | 沿用第一版 |
| 加入阈值 | 余弦 0.30（TF-IDF）/ 0.75（embedding） | `EVOSCIENTIST_L2_CLUSTER_JOIN` / `..._JOIN_EMBED` | 见下 |
| 产生 L2 的最小类 | 3 条 L1 | `EVOSCIENTIST_L2_CLUSTER_MIN_SIZE` | 2 条时归纳基本是把两条拼在一起 |
| 类的上限 | 12 条 L1 | `EVOSCIENTIST_L2_CLUSTER_MAX_SIZE` | 控制单次 prompt 长度 |
| 类内一致性下限 | 平均余弦 0.40（TF-IDF）/ 0.78（embedding） | `EVOSCIENTIST_L2_CLUSTER_COHESION` / `..._COHESION_EMBED` | 离线测量 |
| 更新比例 | 上次规模的 0.5，至少 2 条 | `EVOSCIENTIST_L2_UPDATE_SHARE` | 设计选择 |
| 每类 L2 上限 | 3 条 | — | 沿用第一版 |
| LLM 并发 | 6 | `EVOSCIENTIST_CROSS_PAPER_CONCURRENCY` | 沿用第一版 |

加入阈值和最小类是在 judgelab 的 L1 库（2,697 条 L1，587 篇论文）上测的，下表是不同组合下产生 L2 的类数和覆盖的 L1：

| 最小类 | 加入阈值 0.25 | 加入阈值 0.30 |
|---|---|---|
| 2 | 495 类，60% | 396 类，41% |
| **3** | 249 类，42% | **168 类，24%** |
| 4 | 144 类，30% | 73 类，13% |
| 5 | 78 类，20% | 36 类，8% |

0.30 下抽样看过几个类，内容属于同一主题；0.25 的类内一致性还没看过。按每批 15 条入库回放时，0.30 / 3 得到 167 个
达到 3 条的类，其中 98 个只来自一篇论文，最大的类 10 条。其余 L1 在只有一两条的类里等待；库变大以后，小类会长到门槛。

embedding（Qwen3-Embedding-0.6B）的阈值在同一个库上测（2,697 条 L1，587 篇论文，每批 15 条入库回放，最小类 3）。
最近邻余弦的中位数是 0.79，任意两条之间的中位数 0.37：

| 加入阈值 | 类数 | 达到 3 条的类 | 覆盖 L1 | 其中跨论文 | 达标类的平均一致性 |
|---|---|---|---|---|---|
| 0.70 | 821 | 321 | 78% | 251 | 0.873 |
| 0.72 | 987 | 310 | 71% | 241 | 0.882 |
| **0.75** | **1,309** | **272** | **56%** | **181** | **0.899** |
| 0.78 | 1,700 | 223 | 38% | 122 | 0.917 |
| 0.80 | 1,933 | 177 | 28% | 96 | 0.927 |

一致性下限在 0.75–0.80 之间对结果几乎没有影响（达标类的一致性都在 0.83 以上，拆分主要由 12 条的上限触发），取 0.78。
选 0.75：达到 3 条的类比 TF-IDF 0.30 多 62%（272 vs 168），覆盖从 24% 升到 56%，跨论文的类多数（181/272）；抽查的
类（手写识别的数据增强、时序预测里已知协变量的注意力、增量学习的遗忘、长上下文语言模型的分析）都是同一主题，类内
一致性最低的两个类（0.833、0.840）也是。0.70 覆盖更多，但还没看过类内是否混了主题。

## 8. 验证

已做：

- 单元测试（`tests/test_cross_paper.py`，脚本化模型）：归入、拆分、到期规则、至少 3 条、单篇论文也能产生 L2、首次归纳
  不带 `current_findings`、更新时带上现有 L2、一条新成员只等待、版本延续、退役、失败重试、旧 state 迁移、默认开关。
- 离线：§7 的阈值测量和调用次数回放，都只用聚类，没有调用 LLM。

还没做：

1. 用真实模型在 judgelab 库的若干类上做首次归纳，人工 + LLM 抽查：L2 是否忠实于所引 L1、是不是只是复述其中一条、
   是否真的写出了共性。
2. 对同一批类再加 2 条新 L1 触发更新，检查没受影响的结论是否保持原措辞、已有条件和局限是否被丢掉。代码里目前没有
   防删减的检查（第一版要求修订后长度不少于原来的 60%），只靠 prompt 约束；如果第 2 步发现删减，再加回来。
3. 在线：实验臂 6 小时，统计触发次数、L2 数量、被 plan review 引用的次数，以及 writer 对引用它们的建议的采纳情况。

## 9. 和第一版的差别

| | 第一版（`c4fba3d`） | 本版 |
|---|---|---|
| L2 来源 | 论文原文直接抽 + 跨论文归纳 | 只从 L1 聚类归纳 |
| 分组 | 词面提名候选边，LLM 分组，LLM 指派新记录 | 聚类中心，归入和拆分都在代码里完成，不调用 LLM |
| 来源要求 | 至少 2 篇不同论文 | 不限来源，只要求至少 3 条 L1 |
| 更新 | 每次有新成员，逐条 L2 调用 KEEP / REVISE / ADD_CONFLICT / RETIRE；每 3 次触发全量重建 | 攒够新成员再更新，模型在现有 L2 上修改；拆分时立即更新；没有定期全量重建 |
| 默认开关 | 关 | 开 |
| prompt | `l2_cross_paper{,_group,_assign,_revise}.md` 四个 | `l2_from_l1_cluster.md` 一个 |

本版去掉了定期全量重建。聚类中心每次触发都按当前 IDF 重算，拆分也在持续进行，类不会像第一版的 LLM 分组那样固定下来；
如果验证时发现增量结果和全量重建差别大，再考虑加回来。

## 10. Embedding 服务

聚类和检索共用一个 embedding 服务，默认 Qwen3-Embedding-0.6B（1024 维）：

- 服务：`scripts/embedding_server.py`，OpenAI 兼容的 `/v1/embeddings`，CUDA > MPS > CPU。它在自己的环境里跑
  （torch、sentence-transformers），agent 的环境不需要 torch。也可以用 vLLM / TEI 等任何同一接口的服务。
- 客户端：`EvoScientist/memory/embedding.py`。`EVOSCIENTIST_EMBEDDING_URL` 不设就完全不用 embedding，行为和以前一样。
  查询按 Qwen3 的格式加 instruction（`Instruct: …\nQuery:…`），文档不加。向量缓存在
  `<memory_dir>/embeddings/<model>.sqlite`，按发送的原文的 SHA-256 索引；服务失败时 60 秒内不再请求，退回词法。
- 检索：`search_experience`（以及走它的 plan review）和 `search_paper_text` 在词法排序之外加一路 embedding 排序，
  两路做 RRF 融合（k=60）；正则模式不变。`memory/dense.py`。
- 预编码：`scripts/embed_library.py --project P-…` 把一个项目的经验记录、聚类视图和论文分块先编码进缓存。

检索的离线对比（judgelab 库 2,697 条 L1，随机 300 条，以记录的 `problem` 为查询，文档是去掉 `problem` 后的记录，
即查询和文档没有共同的原文）：

| | hit@1 | hit@10 | MRR |
|---|---|---|---|
| 词法 | 0.290 | 0.647 | 0.404 |
| 词法 + embedding（RRF） | 0.447 | 0.840 | 0.570 |
| 只用 embedding | 0.490 | 0.867 | 0.617 |

这个对比偏向 embedding：查询是同一条记录的另一个字段，措辞不同但讲的是一件事。真实的查询（plan 里的设计选择、
agent 自己写的问题）和记录的关系更松，融合保留了词法对专有名词（数据集名、方法名）的精确命中，所以默认用融合。

在 Mac（M 系列，MPS，fp16）上：编码 2,697 条记录约 6.5 分钟（只做一次），之后一次查询约 0.2 秒。

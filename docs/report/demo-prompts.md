## A · experience-answer · 查经验库答题

**功能**：拿现成经验库回答问题，输出答案 + 依据链（用了哪几条经验、来自哪篇论文、怎么推出结论）。

### A1 · 代码评测指标 ★ 最推荐开场

```
用经验库回答：评估代码生成模型时，用 BLEU 分数靠谱吗？该用什么指标？
```

- **实测召回**：首条 **74.8** 分，>25 分共 5 条
- **看点**：库中有**三条来自不同论文**的经验都指向"BLEU 不适合评代码"，多来源交叉印证
- **耗时**：1–2 分钟

### A2 · 训练数据质量 vs 数量

```
用经验库回答：做指令微调时，数据质量和数量哪个更重要？少量高质量数据够用吗？
```

- **实测召回**：首条 41.2 分，>25 分共 5 条
- **看点**：`[conditional]` 类断言，会给出明确的条件边界（多少条数据是分水岭）
- **耗时**：1–2 分钟

### A3 · GUI 自动化

```
用经验库回答：做 GUI 自动化 agent，纯视觉方案（截图+点击坐标）可行吗？关键难点是什么？
```

- **实测召回**：首条 **57.7** 分，>25 分共 5 条
- **看点**：会讲到 GUI grounding 预训练这个关键前提
- **耗时**：1–2 分钟

### A4 · 多智能体协作

```
用经验库回答：多个 LLM agent 协作时，怎么组织分工？有哪些已验证的拓扑结构？
```

- **实测召回**：首条 **50.2** 分，>25 分共 5 条
- **耗时**：1–2 分钟

### A5 · 端侧部署

```
用经验库回答：把多模态模型部署到手机端，性能瓶颈在哪？有哪些优化手段？
```

- **实测召回**：首条 **65.7** 分
- **看点**：一整套端侧优化组合 + 明确指出首要瓶颈环节
- **耗时**：1–2 分钟

### A6 · 诚实边界 ★★ 建议一定要演

```
用经验库回答：如何优化 CUDA kernel 的访存合并？
```

- **实测召回**：首条仅 **17.0** 分（一条讲手征扰动理论的**物理论文**）
- **为什么必演**：库中完全没有 CUDA 内容。但检索是关键词匹配，**不会返回零命中而是返回噪音**。系统应明说"经验库未覆盖"、逐条说明为何不相关、列出缺口、给出补库路径 —— **可信度来自知道自己不知道什么**
- **耗时**：< 1 分钟

## B · paper-experience · 抽取论文经验

**功能**：论文 → L1 实践经验（做了什么/得到什么）+ L2 归纳经验（什么规律/为什么）。

### B1 · 单篇直给（入口 A）

```
抽取这篇论文的经验 https://arxiv.org/abs/2201.11903。自己执行不要派 subagent。
```

- 这是 Chain-of-Thought 原始论文，全文已抓好（120K 字符）
- **耗时**：2–3 分钟（真实 LLM 抽取）
- **看点**：L1 带 `granularity`（coarse/medium/fine）分级，L2 带 `claim_type` + 置信度 `μ` + 因果解释 `r`

### B2 · 抽取 + 中英双语展示

```
抽取这篇论文的经验 https://arxiv.org/abs/2005.11401，然后展示 2 条 L1 和 2 条 L2，
完整给出每条的 narrative（不要压缩），中英文对照，source_quote 保留英文原文。
自己执行不要派 subagent。
```

- 这是 RAG 原始论文，全文已抓好（87K 字符）
- **耗时**：3–4 分钟
- **看点**：narrative ≥450 词自包含叙述、原文引用不翻译

### B3 · 主题驱动（入口 B）

```
用 paper-experience 技能入口 B：搜索主题 "LLM agent memory management long-term"，
只取排名第 1 的 1 篇，抓全文后抽取经验。自己执行不要派 subagent。
```

- **耗时**：3–5 分钟（搜索约 90 秒 + 抓取秒级 + 抽取 2–3 分钟）
- **看点**：完整链路 —— 搜索 → 取 top-1 → 抓全文 → 抽取

### B4 · 抽取 + 沉淀入库（一段式）

```
抽取这篇论文的经验 https://arxiv.org/abs/2201.11903，并沉淀到记忆。
自己执行不要派 subagent。
```

- **看点**：抽完自动写入 observation 记忆库，L1→procedural、L2→semantic，内容 hash 去重
- **耗时**：3–4 分钟

### B5 · 追加沉淀（追加式）

> 在 B1/B2/B3 任一条跑完后紧接着发

```
把刚才抽的经验沉淀到记忆。
```

- **看点**：不重新抽取（缓存还在磁盘），直接沉淀；会报告 Created / Duplicate 条数
- **耗时**：< 1 分钟

## C · solution-ab · 经验 vs 原文 方案对比

**功能**：同一问题、同一骨架，只换上下文各出一份方案，分列对比。**不判胜负**，评判权留给人。

### C1 · 单篇对比

```
用 solution-ab，论文 2410.01242，问题是"如何让 coding agent 从执行失败中迭代改进"，
分列对比。自己执行不要派 subagent。
```

- 该论文经验与全文均已就位
- **耗时**：3–5 分钟（两次长上下文生成）
- **看点**：会标注规模差异（此篇经验比正文长 53%，超 35% 容差会明确提示"对比非等长"）

### C2 · 多篇合并对比 ★ 更有说服力

```
用 solution-ab，论文 2509.25370,2411.19547,2607.16387，
问题是"如何让 LLM agent 从执行失败中迭代改进"，分列对比。
自己执行不要派 subagent。
```

- 三篇互补：诊断 → 训练信号 → 改进机制
- **实测**：去噪后 A 组 168,974 / B 组 138,855 字符，差异 **21.7%（容差内）**
- **耗时**：5–8 分钟
- **已知结论**：A 组（经验）擅长**抽象成可复用架构**（三篇合成的闭环原文里没有任何一篇提出过）；B 组（原文）保住**可复现配置**（`κ≥0.75`、`5e-5→5e-6` 余弦退火）。关键数值在 A 组出现 19 次、B 组 1 次 —— 经验把数值反复带在多个自包含叙述里

### C3 · 链式触发（从抽取直接接到对比）

```
用 paper-experience 搜索主题 "code repair from test failure feedback"，取 2 篇，
抽取经验，并对比经验和原文各自生成的方案，分列展示。
自己执行不要派 subagent。
```

- **看点**：显式要求对比才会链式转交（裸的"抽取经验"不触发）
- **耗时**：8–12 分钟（搜索 + 2 篇抽取 + 2 次长生成）

## 现场应急

| 情况 | 处置 |
|---|---|
| 报 `Connection error` | 代理偶发断连，重发一次即可 |
| Agent 想派 subagent | 提示词已含"自己执行不要派 subagent"；若仍派，追加一句"直接自己调工具，不要用 task" |
| 抽取超过 5 分钟无响应 | 长上下文生成较慢，可等；或换 A 组（纯检索，秒级） |
| 需要秒级出结果 | 只用 A 组 —— 不调抽取 LLM，只做检索 + 答案生成 |
